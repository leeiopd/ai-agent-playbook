# 프로젝트 지침 구조 규약

모든 프로젝트에서 에이전트/공통 지침 파일은 아래 구조를 따른다. **신규·기존 프로젝트 모두 상시 적용**한다.

## 가시 위치 (root/docs — 각 도구가 읽기로 약속한 자리. dot-숨김 금지)

- **`AGENTS.md`** (root) — **범용 지침 원본**. Codex, Cursor, Gemini CLI 등 대부분의 에이전트 툴이 기본으로 읽는 크로스툴 표준 파일. 규칙·워크플로우의 단일 진실 공급원(single source of truth)으로 삼는다.
- **`CLAUDE.md`** (root, 선택) — Claude Code 전용 진입점이 필요하면 `@AGENTS.md`로 본문을 흡수한다(중복 작성 금지). 다른 도구도 각자의 관례 파일(`.cursor/rules`, `GEMINI.md` 등)이 필요하면 같은 방식으로 `AGENTS.md`를 가리키게 한다.
- **`CONTEXT.md`** (root) — 도메인 용어집(유비쿼터스 언어).
- **`docs/PRD.md`**, **`docs/issues/`** — 스펙과 이슈 티켓(로컬 마크다운 트래커를 쓰는 경우).
- **`docs/agents/`** — 특정 워크플로우/스킬이 소비하는 세부 규칙 문서.

## 명령어 예산과 progressive disclosure

프론티어 LLM이 일관되게 따를 수 있는 지침 개수에는 한계가 있고(대략 150~200개), `AGENTS.md`의 모든 토큰은 요청마다 로드된다. 따라서:

- 루트 `AGENTS.md`에는 **항상 적용되는 규칙**만 남긴다.
- 특정 상황(코드 리뷰, 새 모듈 설계, 기존 코드 영향 범위 조사 등)에서만 필요한 상세 규칙은 `docs/*.md`로 분리하고, 루트에는 한두 줄 요약 + 링크만 둔다.
- 파일이 오래돼 규칙이 쌓이기만 하고 정리가 안 됐다면(개발자마다 추가한 규칙이 뒤섞여 "진흙탕"이 된 상태), 주기적으로 모순 확인 → 본질만 추출 → 도메인별 재그룹 → 분리 파일로 재구성한다.
- 파일 경로를 지침에 박아두지 않는다. 파일은 이동하지만 도메인 개념은 상대적으로 안정적이다.

## 숨김 위치 (`.claude/`, `.codex/` 등 — 툴 전용, 지침 두지 않음)

- 공유 툴 설정(`launch.json` 등)·개인 설정만 둔다.
- `.gitignore`에 추가하되 공유해야 할 파일은 negation 예외로 명시한다.

## 원칙

프로젝트 **공통 지침은 dot-숨김 위치(`.claude/`, `.codex/` 등)에 두지 않는다.** 가시적이면서 *도구가 약속한 위치*(root/docs)여야 한다 — 숨기면 사람도, 다른 에이전트 툴도 못 읽는다.

지침의 본문은 **도구 중립적인 `AGENTS.md` 하나**에 두고, 도구별 진입점 파일은 그것을 가리키기만 하는 얇은 래퍼로 유지한다. 이렇게 하면 팀에서 어떤 에이전트를 쓰든(같은 사람이 Claude Code와 Codex를 오가는 경우 포함) 규칙이 갈라지지 않는다.

프로젝트 고유 *내용*(용어집 항목·스펙 본문)은 각 레포에 두고, 이 **구조 규약**만 여러 프로젝트에 공통 적용한다.
